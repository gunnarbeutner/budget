# Production wiring of the browser sidecar (review input for the infra repo)

The prod compose file of mars is generated by the beutner-infra repo; these files are input to review and merge there,
not to deploy from here. Background: `docs/browser-sidecar.md`.

1. Secret: `openssl rand -hex 32`. Store it twice via SOPS (`beutner-infra.mars.yaml`, `secret_configuration_catalog`):
   `Browser__Remote__Token=<value>` for the app, `SELKIES_MASTER_TOKEN=<value>` for the sidecar.
2. Install `seccomp_profile.json` to `/docker/budget/` (`host_configuration_catalog`).
3. Merge `compose.mars.yaml` into the budget compose file: the new `browser` service, and the app's two
   `Browser__Remote__*` URLs plus the secret file. Set `SELKIES_ALLOWED_ORIGINS` to the app's public origin.
4. Add the `budget-browser` image deployment (`compose_deployments`); it builds `docker/browser/`.
5. Apache: the stream's WebSocket goes through the app at `/weblogin/desktop/api/websockets`. If the vhost does not
   already upgrade WebSockets for all paths, add before the catch-all `ProxyPass /`:

   ```apache
   ProxyPass /weblogin/desktop/api/websockets http://127.0.0.1:<app port>/weblogin/desktop/api/websockets upgrade=websocket timeout=600
   ProxyPassReverse /weblogin/desktop/api/websockets http://127.0.0.1:<app port>/weblogin/desktop/api/websockets
   ```

   Keep tokens out of logs: the stream page carries its token in the URL fragment (never sent), but avoid logging
   query strings and cookies for this path.
6. Deploy the browser first, then the app: the app has no other way to run web logins, so without a working sidecar
   (or without the `Browser__Remote__*` settings) every web login fails with an error; FinTS, API connectors and the
   rest of the app keep working. Rollback: deploy the previous app and browser images together. Kept profiles stay
   in `data/browser-profiles/` either way; nothing to migrate.
